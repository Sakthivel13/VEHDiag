Hardware abstraction

One engine, any adapter

The diagnostic engine never talks to hardware directly. It talks to an AdapterInterface — transport plugs in as a driver.

ELM327 — Bluetooth

Classic SPP and BLE ELM327 v1.4+ adapters via BluetoothAdapter. Auto-baud, protocol detection, adaptive timeouts.

AT commands · SPP · BLE

ELM327 — USB

USB-serial (FTDI, CP210x, CH340) and USB CDC adapters via USBAdapter.

USB serial

ELM327 — WiFi / TCP

ELM327 over WiFi or raw TCP sockets (port 35000 default) — the same transport the web dashboard uses for remote sessions.

TCP 35000

CAN interfaces

Hardware abstraction for raw CAN: SocketCAN, PCAN, Kvaser, Vector — plus a simulation bus. J1939/DBC-style signal definitions plug into the same live-data engine.

CAN HAL

VEHDiag Simulator

A full virtual vehicle speaking real ELM327 AT/OBD commands — ECUs, DTCs, live signals, VIN, fault injection, timeouts and NRC responses. Zero hardware required.

virtual ECU

Vendor adapters

A stable AdapterInterface (connect, send, receive, timeout, disconnect, events) so vendor-specific transports plug in without touching diagnostic logic.

interface contract
